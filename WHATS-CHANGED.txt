Video Trim Studio - Word highlight + export without trimming
==========================================================================

Replace these files in your project folder (same paths):

    static/index.html         <- Inspector > Typography: the new "Word
                                 highlight" group; the Text animation menu's
                                 "Karaoke" entry is now "Word highlight"
                                 (?v= bumped to 55)
    static/app.js             <- the preview draws whatever the burn draws:
                                 accent colour, background marker or both,
                                 current word or all spoken words, marker
                                 colour / opacity / padding / roundness (?v=55)
    static/style.css          <- the marker layer (.cap-word-bg) and the
                                 glyph layer (.cap-word-tx) (?v=55)
    vts/captionmap.py         <- per-word ASS events: a rounded \p1 marker on
                                 layer 0, the word on layer 1, both at the same
                                 x, so the box never drifts off the word
    vts/captions.py           <- the six new style keys, validated and clamped;
                                 legacy anim_words "karaoke" is read as "word"
    vts/edl.py                <- export fix: the stream-copy fast path accepts
                                 the bin resolver's (path, kind, has_audio) and
                                 the "why it re-encoded" note names the real
                                 reason
    vts/export.py             <- export fix: an empty cut list means "keep the
                                 whole video" instead of "Nothing selected to
                                 delete."; an empty encoder falls back to
                                 libx264
    README.md                 <- docs
    tests/test_caption.py     <- burn tests: geometry, marker path, colour,
                                 opacity, padding/radius clamps, legacy parity
    tests/test_word_highlight_ui.py  <- NEW: the preview in a real browser
    tests/test_timeline_ui.py <- one assertion: the menu now stores "word"
    tests/test_timeline.py    <- NEW tests: untrimmed export, 3-tuple resolver,
                                 the note naming burned captions
    tests/test_api.py         <- NEW tests: /api/export with nothing cut
    tests/test_pipeline.py    <- empty cut list is a job, cutting it all is not
    WHATS-CHANGED.txt         <- this file

Then reload http://127.0.0.1:8765/ with Ctrl+F5. No server restart and no
`pip install` are needed.


1) What the old "Karaoke" did
-----------------------------
It recoloured the word being spoken - permanently. You could pick the colour,
and that was it: every word in the caption ended up that colour as the take
played, and there was no way to put a box behind the word instead.

"Karaoke" is now called **Word highlight** (Text animation > Words), and it is
a small style of its own under Typography.


2) New: Inspector > Typography > Word highlight
-----------------------------------------------
    Mark      Colour the word | Background marker | Colour + marker
    Span      Current word | All spoken words
    Colour    the accent ink (the old highlight colour, #ffd400 by default)
    Marker    the box colour (#101418) + its own opacity (85 %)
    Marker padding     % of the text size, 0-40   (12)
    Marker roundness   % of the text size, 0-50   (22)

  Mark        "Background marker" paints only the box and leaves the glyphs in
              the caption's own fill, so the word is marked without turning
              yellow. "Colour + marker" does both. "Colour the word" is the
              original karaoke look.
  Span        "Current word" is the karaoke behaviour - one word lit at a time.
              "All spoken words" keeps every word heard so far marked, like a
              read-along line that fills in as it plays (and stays marked
              through a pause between words, exactly like the burn).
  Marker      The box hugs the word: padding grows it on all four sides,
              roundness turns it from a square slab into a pill.

  Every one of the six values is written into the caption style, follows the
  **Apply to all captions** switch like the rest of the Typography section,
  is saved with the project and is used by the export.


3) Preview and export are the same picture
-------------------------------------------
The burn no longer uses libass's \k karaoke tags (they cannot paint a rounded
box). For each word the .ass gets two events:

    layer 0   the marker:  {\an7\pos(...)\p1\1c&H101418&\1a&H26&}m ... l ...
    layer 1   the word:    {\an5\pos(...)\1c&HFFD400&}terus{\1c&HFFFFFF&}

Both use the same x, computed once from the same font advance, so the box can
never sit off-centre. The marker is a cubic-bezier rounded rectangle; a
roundness that would exceed half the box is clamped to a pill, and padding 0
gives square corners.

The preview uses the same numbers: padding and roundness are applied as em
values (the burn's "% of font size"), the box is its own absolutely positioned
layer behind the glyphs (so the word never shifts), and the marker colour is
composited with its opacity. The old karaoke glow around the spoken word is
gone as well - the mark is the colour and/or the box, with no halo the burn
does not draw. The word that is "current" in the preview is
picked the same way the burn picks it: the last word whose start has passed,
holding until the next word starts.


4) Backwards compatibility
--------------------------
- Projects saved before this change store `anim_words: "karaoke"`. They still
  open and burn identically: the loader and the style cleaner read "karaoke"
  as "word", and the preview accepts both spellings.
- The default look is unchanged: accent colour only, current word, #ffd400.
  A caption that never touched the new controls burns the same frame it did
  before - the tests check that parity directly (same events, same timings).
- The six new keys are validated on the way in: unknown values fall back to
  the defaults, padding is clamped to 0-40, roundness to 0-50, and a marker
  colour that is not a #rrggbb hex falls back to #101418.

6) Export without trimming (the "it forces me to trim" bug)
-----------------------------------------------------------
Two separate defects made a no-trim export impossible. Both are fixed.

  a) Exporting an untouched clip died with HTTP 500.
     The stream-copy fast path unpacks the media resolver as `paths, kind`,
     but the resolver has answered `(path, kind, has_audio)` since the media
     bin landed. Any export that needed no re-encode - one clip, no cuts, no
     effects, no burned captions - raised
         ValueError: too many values to unpack (expected 2)
     and the UI only ever showed "Internal Server Error". Cutting the video
     (or burning captions) forced the re-encode path, which handled the
     three values correctly, so trimming *appeared* to be mandatory.
     `_copy_fast_path` now reads the tuple by position and still accepts the
     old two-value form.

  b) The clean-cut exporter rejected an empty cut list.
     `vts/export.py` refused to start when nothing was marked for deletion
     ("Nothing selected to delete."). An empty list is now a normal job: it
     keeps the whole video, which is exactly what "burn these captions on my
     file" needs. Deleting *everything* is still refused.

While in there:

  - The "stream copy was upgraded" note used to blame "clip effects /
    keyframes" whatever the cause. It now names the real one - "burned-in
    captions", "a clip that does not start at 0", "a still image", "audio
    items on their own lanes", ...
  - An empty encoder picker no longer reaches ffmpeg as `-c:v ""`
    ("Unknown encoder ''"); it falls back to libx264. On a machine with no
    hardware encoder this is what a burn export uses.

What this means in practice: open a video, type or import captions, set
Export > burn, press Export - with no cut at all. A plain no-caption export of
an untouched clip stays a stream copy (instant, no quality loss); burning
captions re-encodes, and says so.

Tests: tests/test_timeline.py (untrimmed export through the real resolver,
burn note), tests/test_api.py (/api/export and /api/export/timeline with
nothing cut) and tests/test_pipeline.py (empty list exports, total cut refused)
all pass alongside the existing suites.
